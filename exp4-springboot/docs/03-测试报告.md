执行命令：`mvn test`（工作目录 `exp4-springboot/backend`）

**结果：Tests run: 28, Failures: 0, Errors: 0, Skipped: 0 — BUILD SUCCESS**

| 测试类 | 用例 | 验证点 |
|---|---|---|
| `OrderStatusTest` | 6 | 订单状态机合法流转；不许跳过支付；终态不可流转；已支付不可取消；商品可购买/可议价规则 |
| `JwtUtilTest` | 4 | 签发解析一致；**换密钥验签失败（防伪造）**；过期令牌被拒；篡改令牌被拒 |
| `WalletServiceImplTest` | 4 | 扣款成功写负数流水且 `balanceAfter` 正确；**余额不足抛 2004 且不写流水**；非正金额拒绝；入账写正数流水 |
| `BargainServiceImplTest` | 5 | 接受报价生成议价订单（金额=报价、origin=BARGAIN、offerId 落库）；**商品 CAS 失败则不生成订单**；非卖家接受被拒（2003）；出价次数上限；出价必须低于售价 |
| `AuthServiceImplTest` | 5 | 登录成功返回 token/角色/权限；密码错误统一提示；用户不存在同一提示（防枚举）；禁用账号拒绝；失败 5 次限流（1005） |
| `AuthControllerTest` | 4 | 登录返回 `code=0`；空用户名/短密码返回 1001；非法 JSON 返回 1001 而非 500 |

### 单元测试覆盖的关键不变量

1. **资金安全**：扣款与记账必须同时成功或同时失败；余额不足不得产生流水。
2. **并发安全**：商品/订单/报价单三处 CAS 失败路径都断言"不得继续后续写操作"。
3. **鉴权边界**：越权接受报价必须在写任何数据之前被拦截。
4. **令牌安全**：密钥不同、过期、被篡改三种情况都必须解析失败。

## 4 第三轮：全流程回归（26 项，PASS=26 / FAIL=0）

按真实使用顺序串起来跑一遍：注册 → 发布 → 审核 → 浏览 → 收藏 → 下单 → 支付 → 发货 → 收货 → 评价 → 议价（人工 + 自动）→ 通知 → 看板 → 上传删除。

| 分组 | 用例数 | 关键断言 | 结果 |
|---|---|---|---|
| A 权限矩阵 | 6 | 超管 31 项含收藏/消息；管理员 12 项无钱包；USER 20 项含发布；USER 无审计权限 | 全 PASS |
| B 注册→发布→审核 | 5 | 注册仅 USER；发布为 PENDING；**不填意见审核 code=0**；上架成功；卖家见底价 80、买家不可见 | 全 PASS |
| C 防刷/收藏/404 | 4 | 连续两次详情浏览量不变（1→1）；收藏成功；不存在的静态资源返回 **404** | 全 PASS |
| D 交易闭环 | 5 | 下单 UNPAID；支付扣 100（1200→1100）；发货、收货后 COMPLETED；卖家收到买家评价 | 全 PASS |
| E 议价两条路径 | 4 | 低于底价→PENDING 且卖家接受可成单；≥底价→`autoAccepted=true` 自动生成订单；商品锁定后他人无法再议价 | 全 PASS |
| F 通知/看板/上传 | 3 | 未读 9 条；看板 GMV=220；上传后删除返回 404 | 全 PASS |

> 说明：本轮测试数据（`flowuser`、3 个 Flow 商品、若干订单/评价）保留在库中；需要干净演示态时重跑 `sql/exp4_trade.sql` 即可。
